## Current construction campaigns

**Search is oriented toward finding a verified <270 cover.** The 270-block baseline has 4,640 uniquely covered 7-sets. Its weakest four blocks each protect exactly 2 unique 7-sets. Every baseline block's uniquely covered 7-sets involve all nine of its points, so no block can be replaced by a *different single block* while all other blocks are frozen.

1. **CP-SAT collective repair**, `search.py`: freeze most blocks, release 12–60 at a time and optimize an exact residual covering. Seeds 15 and 1515: [Actions run](https://github.com/teddyli18000/web-ingest/actions/runs/43240551383).
2. **Decremental weighted local search**, `run_wls.py`: retrieve the public MIT-licensed 2026 `wls2` solver and try focused point swaps in four seeded, 850-second searches. [Actions run](https://github.com/teddyli18000/web-ingest/actions/runs/43241334357). All 4 runs completed and their independently verified score was **270**. This route has not produced the desired construction.
3. **Global multi-parent recombination**, `recombine.py`: merge the original covering with 1–2 relabeled high-quality coverings into a 500–800-variable set-cover instance, require genuine mixing, and optimize across the joint candidate family rather than locally swapping blocks. Four CP-SAT shards finished with only UNKNOWN statuses (no new mixed full covering): [Actions run](https://github.com/teddyli18000/web-ingest/actions/runs/43244817454). The intent is either a 269 covering or a structurally distant new 270 parent for further search.
4. **Full-block and coordinated exchanges:** a separate local C++ whole-block weighted search has repeatedly approached 2 uncovered 7-sets at size 269 but not closed both. Two-for-two complete-cover exchanges do produce alternative full covers but remain only about 6 blocks distant from the published parent after hundreds of accepted swaps. Exhaustive three-for-two exchanges of the initial baseline tried all 3,244,140 triples (verified independently by removal counts) and found no 269 witness. This restricts only that particular construction's small exchange neighborhood, not the global problem. Four-for-three constructive enumeration of the 120 least-exclusive baseline blocks produced no improvement. These exact local exclusions prompted a change in representation; do not scale this same search.

5. **Global fixed-269 soft covering**, `soft269.py`: all 5,005 candidates and 6,435 soft constraints, four seeds ×950 seconds starting from 269-block baselines with only two gaps. All four best solutions retained **two gaps** (none a valid covering). [Actions run](https://github.com/teddyli18000/web-ingest/actions/runs/43246501862).
6. **Independent parent construction**, `parent-15-10-8.json`, `extract_ljcr.py`, `projection_search.cpp`: the parent has **253 10-subsets covering all 6,435 8-subsets**, independently verified after zero-based conversion. Optimizing one 9-subset projection per parent then greedily patching the uncovered 7-subsets generates a fully valid *different* 9-cover family. Local 7-second C++ probe obtained 361 total blocks, making it uncompetitive as-is. An [Actions construction-and-shrink run](https://github.com/teddyli18000/web-ingest/actions/runs/43249598262) tests whether weighted deletion from these independent parent constructions can descend below the original 270. If not, prefer a different formulation over repetition.
7. **Dynamic ejection chains**, `ejection_chain.cpp`: start with 269 blocks and two uncovered 7-sets, let the new uncovered sets created by a block insertion/ejection choose the next repair, beam search through temporary gaps, rather than fixing a release neighborhood in advance. Four concurrent seeded beams are running in [Actions](https://github.com/teddyli18000/web-ingest/actions/runs/43251501521). Independently scan each result for the exact number of missing 7-sets; only zero allows Few Shots verification/submission.

The source for `wls2` and its experimental methodology is Wynand van Staden, *Local Search and a Construction Scan for Covering-Design and Lottery-Covering Tables* (posted 2026-10-29), [preprint](https://www.preprints.org/manuscript/202610.2905), [source](https://github.com/WynandVStaden/covering-design-records/).

## Reproducible experiment
`search.py` reads an existing baseline certificate, verifies the input independently, and executes randomized large-neighborhood CP-SAT residual repairs. It writes `best.json`, `history.json`, and `certificate.json` only after a full independent exhaustive coverage check. All 5005 possible 9-subsets are candidate repairs; each 7-subset has 28 covering candidate blocks. Random seed controls the experiment.

One-shot workflow scripts `.github/workflows/temp-p015-*.yml` run the independent search campaigns, emit complete run logs, and upload certificates or near-cover artifacts. No recurring schedule. Remove each temporary workflow after validating its results.

## Constraints and independent validation
Score counts entries including duplicates. Check each block has nine unique integers in 0..14; test coverage of all 6435 7-subsets from scratch. Before Few Shots submission, run its original verifier and `tools/check.py` on a shot directory. No score is claimed merely because an optimizer reports feasible.
