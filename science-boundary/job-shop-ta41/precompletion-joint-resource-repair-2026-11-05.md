# Before-completion coordinated resource repair — 2026-11-05

## Question and construction-first standard

**Can the scheduler identify jointly retractable, mutually dependent machine-precedence decisions *before constructing a full schedule*, then turn those predictions into strictly better legal 30×20 machine orders?** A mathematical obstruction is not a success by itself: primary metric is independently verified strictly improving complete schedules, paired with true published N7 on **independent** strong N7 elite starts, not perturbations of hidden oracle machine orders.

Source/precedent check (2026-11-05): Nagata and Ono (2018), [IEBO](https://doi.org/10.1016/j.cor.2017.09.017), already alternate insertion/ejection in partial schedules and use DP-enumerated necessary ejection sets. Earlier shifting bottleneck, edge-finding, overload reasoning are established. The 2026 [More powerful energetic reasoning for the cumulative scheduling problem](https://doi.org/10.1016/j.dam.2025.07.016) extends interval resource checks, but its methodology is not reproduced here. No claim of a new general ejection principle; the current test combines target-sensitive min-cut dependency closure with CP-SAT repair and compares its specific control-feedback effect.

## What has actually been independently tested

1. **Bidirectionally forbidden resource pairs:** in a partial-order DAG under target L, if for two operations u,v on one machine both `head[u]+p[u]+tail[v]>L` and `head[v]+p[v]+tail[u]>L`, neither possible resource orientation can fit without first retracting some currently fixed machine edge supporting the path bounds. Such pairs yield sound *disjunctive* retracement requirements but do not identify a unique required edge. Code `partial_resource_pair_repair.py`. A 3-policy × 4-instance comparison (ta41 plus 3 independent strong N7 starts) yielded **1 strict improvement**, from **STATIC** ta43 N7 1888→1887. Paired and random policy did not improve within 201 released adjacent arcs.
2. **Precompletion machine-window energetic overload:** if every possible start for a task in [ES,LS] places at least `r_i` units inside machine interval [a,b], and `sum_i r_i>b-a`, the existing partial precedence is incompatible with target L. `energetic_conflicts` computes exact minimum overlap for each operation using window endpoints. All four test cases showed an initial positive overload of just **one time unit**, on one machine. After releasing 21–41 original adjacent arcs, the overload disappeared, but all 11 successive fixed-survivor CP completions per case remained conditionally INFEASIBLE. A logical proof of conflict is not a successful variable selector.
3. **Independent 12-source-witness audit:** `audit_partial_resource_witnesses.py` derives pair/energy explanation masks using only each independent N7 elite start. *After* prediction it compares these masks with a complete better ScheduleOpt machine order, independently DAG-verified. Exactly **8 pair witnesses + 56 energetic-window witnesses** were seen; **all 64 were hit** by at least one actually reversed original adjacent machine relation. Soundness check only for these 12 known witness instances. Top-20 released adjacent arc overlap with archived better order: STATIC original critical 101/240, pair-guided 96/240, energetic 90/240. **Prediction precision is not better than static**; these coarse masks cannot replace more discriminating counterfactual resource reasoning. Source `results/partial-resource-oracle-audit.json`.
4. **Fully coordinated CP with NO frozen survivors:** `joint_soft_pair_completion.py` models *all* 580 incumbent adjacent pair orientations as soft reified decisions, full 600-operation job order and all 20 NoOverlap hard, hard makespan at most incumbent-1; solver separately optimized flips with four policies uniform/static/energetic/CP-assumption-core. Original 12-run one-minute comparison completed: **ta43 N7 1888→1887** for all four policies, with STATIC proving exact minimum weighted orientation cost in 0.795s, energy taking 17.2s, CP core 53.7s and uniform finding feasible in 60s; **ta46 N7 2044→2042** under uniform/static, only **2043** under energetic/core; **ta41 2006→2005 was UNKNOWN** for all four after 60s each. No systematic gain from the extra conflict explanation. Each full output was independently DAG replayed; no Few Shots submission.
5. **True partially scheduled insertion/ejection chains:** `partial_ejection_chain.cpp` permits temporarily removing up to eight operations from their machine lists; all job-chain arcs remain, and every accepted partial state keeps optimistic DAG bound <= incumbent-1. Dynamic selects ejections from the *new* partial critical machine path exposed by inserting an unscheduled op; static focuses on the original path; random samples candidates. Initial 80k-DAG score test with at most one simultaneous ejected operation was flat. Extending to **1–8 simultaneous unscheduled operations, including two simultaneous ejections**, produced 500k-DAG-score × 24 trials per arm on independent author-N7 elite starts. Results: **dynamic 0/24 improved, static 0/24, random 1/24** (ta47js-n7elite1711, 1930→1929). All other 71 completed outputs independent DAG-reproduced. The incomplete state is necessary but not sufficient; this implementation lacks IEBO's original DP enumeration and guided state assessment, and is not claimed to match its quality. This is strong evidence **not** to scale the same blind ejection chain without changing how the jointly released resource constraints are chosen.

## New mechanistic test: exact counterfactual cycle-and-deadline mincut closure

The relevant **representation change** is from ejected *operations* to a **set of jointly retractable machine-precedence arcs**, while targeting a specific counterfactual machine-order reversal.

Let `G(S,R)` be the partial disjunctive DAG with the immutable job arcs, plus incumbent adjacent machine arcs except those in released set R. Let `r=(u→v)` be an incumbent adjacent machine arc proposed for reversal. Before forming a full candidate:

1. Set `R={r}`. The proposed new orientation `v→u` creates a cycle **if and only if** the rest of `G(S,R)` contains a directed path `u→v`. A min u-v cut, giving every mutable resource arc unit capacity and every immutable job arc infinite capacity, finds a **minimum number of currently retained resource arcs** whose retraction disconnects *all* such alternate paths. If the min cut is infinite, the proposed root reversal is impossible because of immutable precedence alone. This is exact for the currently fixed partial-order graph, not a statement about the global JSSP optimum.
2. Now impose `v→u` in that partial DAG. Recompute the exact longest path. If it exceeds the target L, build the entire **current** critical-path subgraph and mincut its machine arcs (job arcs and the proposed reversed root are immutable). Release the cut and **recompute the new longest paths**. Iterate until every presently exposed precedence path is <= L; this explicitly captures *replacement bottlenecks*, rather than repeating a static original critical-path cut.
3. Finally ask the full-resource CP-SAT model for a complete schedule at L: 600 hard job operations, 20 hard NoOverlap resources, proposed root reversed hard, the surviving incumbent adjacent arc constraints as individually retractable assumptions. If UNSAT, the returned sufficient assumption core gives a **new set of resource conditions** that cannot all be retained. Release a matched number of arcs from that core based on **current** partial criticality (`dynamic`), **initial** baseline criticality (`static`), or uniform choice from the core (`random`); re-run exact CP completion under the same resource/deadline budgets.

This is a *constructive* candidate generator with guaranteed sound precompletion graph cuts and independently checked final certificates; it is not a claim of polynomial-time job-shop optimization. CP cores may contain many alternatives and may not be minimal. A CP `UNKNOWN` outcome is not an exclusion. Both positive controls and ta41 remain the objective.

Implementation: `counterfactual_joint_cut.py`; workflow `temp-ta41-counterfactual-cycle-deadline-closure.yml`. First paired test: three methods × two independent source-N7 elite 30×20 starts (ta43 1888, ta46 2044); identical root candidate list, same min-cut preprocessing, 18 root candidates, 6 rounds/root, 5 extra resource-arc releases/core, 1.2s/CP round and 80s total/witness. **No result claimed before workflow completion and independent full-DAG scoring.** A successful method must outperform static under the same hard CP budgets, not merely find larger UNSAT sets.

## Explicit remaining questions

- Does the predicted *counterfactual* cycle + replacement critical-path closure select a released arc set containing one independently verifiable improving completion more reliably than same-budget static/unweighted core-conditioned repair?
- Can an exact mincut basis be reused across roots to amortize counterfactual evaluation, keeping performance competitive with genuine source N7 at a matched 5-second CPU budget?
- Is the active released-set search too coupled to one baseline order, requiring pair-level soft orientation rather than any hard frozen survivor arcs? Previous partial CP experiments showed fast conditional UNSAT even after 201 released baseline adjacent arcs, although a global unfrozen CP found target positive solutions. If the same limitation persists, do not scale this fixed-survivor representation.
- Does source-faithful IEBO code or a historical ta41=2005 raw machine order exist in public archive? Prior documentation and author title are at `positive-transfer-and-2005-archive-2026-11-05.md`; no 2005 witness yet.
