# Taillard ta41 — constructive predictive critical-path cascade, 2026-11-04/05

## Scientific question

**Primary outcome is a new full, independently verified legal schedule with Cmax <=2005.** We no longer aim to grow an exclusion boundary. The falsifiable mechanism claim is: conditional on the first critical-block insertion, predicting which machine resource arcs become newly critical and selecting the *next two* insertions on those replacement bottlenecks is a more productive way of jointly coordinating small modifications than an equal-cost critical-block tabu policy or the same three-step method with the original critical arc focus.

Existing data are strong constraints on research design:
- The 2026-10-29 two-step replacement pilot already ran **528,000 exact evaluations** across 24 arms/parents/seeds and never improved 2006. Merely enlarging two-step budgets is not an advance.
- Fixed-survivor CP LNS after 240 released operations left >300 hard precedence arcs and 8/8 independently found UNSAT cores. Hitting an old core with 2 operation endpoints only caused new cores to appear; 16/16 had independent full-NoOverlap UNSAT replay. These **prove why not to freeze survivor arcs**, not that the global best is distant.
- Full global soft-precedence CP and 14-parent consensus/core feedback have already produced new 2006 neutral states but no 2005. Do not simply rerun those same models.
- Independent exact 2^15 swap lattice proves specific individually harmful swaps become neutral after 1–2 enabling moves at Cmax 2006. This supports coordinated acceptance at macro endpoints, not rejection of intermediate uphill moves.

## Actual new implementation, with explicit controls

- `predictive_cascade_search.cpp`: original compact C++ full-disjunctive-DAG evaluator for ta41, all 600 operations, 570 job precedences, 580 machine-consecutive arcs. Rejects cyclic permutations. Computes head, tail, and all critical machine arcs on accepted/tentative states. All output stays legal machine-order permutations.
- `run_predictive_cascade.py`: constructs **identical ta41 routing and durations** via existing `search.obtain()`, supplies one of three *official Few Shots verified* 2006 parents (`baseline`, `gateway124`, `ninecore`), executes binary and independently verifies every resulting schedule with `search.evaluate()`; any <=2005 certificate is checked separately by upstream Few Shots official verifier before claim.
- **tabu:** N7-inspired critical-block insertion neighborhood, tabu rejection for recent reverse moves, aspiration when improving the global best, randomized tenure 8–20, global best restarts with up to 80 distinct elite schedules.
- **static3:** three successive machine insertions treated as ONE atomic macro; original parent's critical machine edges guide steps two and three. Intermediate scores may deteriorate, and acceptance evaluates only final legal schedule.
- **dynamic3:** same macro generation/budgets, except after tentative first and second moves it recomputes the entire exact critical machine arc set, constructs `new = Critical(child) \ Critical(parent)`, and preferentially proposes subsequent critical-block insertions on these *new* resource bottlenecks. The move focus is applied inside the same macro, not at a later restart. The final complete DAG score alone determines record improvement.
- All three arms use the same exact evaluator and operation-insertion kernel with a shared criterion: best legal makespan. Each is allotted **1,000,000 candidate DAG evaluations**, same parent and seeds 4107/4113. Each experiment records CPU elapsed separately because looking deeper has different overhead; matched-evaluation and matched-wall-clock summaries must be distinguished.
- 3 policies × 3 parents × 2 seeds = **18 controlled trials** in six parallel 3-policy Actions jobs. Stronger outside reference: original author C++ NDS-S random/heuristic 100,000 iterations each from 2006, both 2006; original checkpoint warmstart 120s also remained 2006. Those are **not matched-budget benchmarks**, so don't use them to claim statistical superiority.
- The essential evaluation is (a) new independent 2005 certificate yes/no, (b) comparable best score vs tabu and static3, (c) time/evaluation, (d) neutral and critical-path migration statistics. Counts of newly critical arcs alone are **not objective performance**.
- Single smoke matrix (`temp-ta41-cascade-smoke.yml`, run `41987285813`) completed successfully for all 3 policies with 2500 candidate evaluations, identical Python/C++ makespan 2006. Full matched experimental workflow: `temp-ta41-cascade-matched-benchmark.yml`, run `41987492659`; status must be checked before claiming results.
- Beware: three-hop dynamic is still an **approximate N7-style insertion generator** not yet a faithful official N7/LLG2026 reproduction. A zero-advantage result on only two seeds is weak evidence; if all fail, next move should be an alternative **joint search representation** (predictor-conditioned full CP soft arc repair, or multi-parent path relinking) rather than merely extending the same local insertion loops.

## Completed constructive experiments — independent machine-order scoring and no new 2005

All raw outcomes, exact score/evaluation counts, original C++ code and official checker verdicts are under `science-boundary/job-shop-ta41/results/` on `main`. The source of truth is the saved `summary.json`; every candidate produced by C++ is *again* scored using the original `search.evaluate` implementation.

**Stage A: N7-inspired critical-block tabu vs three-move coordinated critical replacement.**

Workflow `temp-ta41-cascade-matched-benchmark.yml` run `41987492659`: **18 / 18** successful tests, 3 policy variants × 3 independently officially verified score-2006 starting schedules × 2 seeds [4107, 4113]. Exactly **1,000,000 full-DAG candidate evaluations per trial = 18,000,000 total**. The original `tabu`, `static3` and `dynamic3` policy ALL yielded **2006**, with no improved certificate and no winner. Time per million about 3–6.5 C++ seconds. Dynamic3 did accept many intermediate uphill three-operation macros, often returning to score 2006, but this produced no benefit to final objective. The internal C++ tabu is **N7-inspired**, not the true authors' source-code implementation or a proven external state-of-art baseline.

**Stage B: interleave diverse elite machine orders via path relinking and predict newly created bottlenecks.**

Original `elite_replacement_relink.cpp` uses the same fully legal exact DAG evaluator. Two policies:
- `greedy`: on a target-directed path between two verified 2006 schedules, score all (or up to 200) valid one-adjacent-inversion moves, select the best.
- `dynamic2`: score a hypothetical first move, compute the newly critical machine arcs, then prioritize a second target-directed inversion involving that resource, accepting the pair atomically.

`temp-ta41-elite-path-replacement-matched.yml` run `41988711358` completed 6 / 6 trials × **2 million candidate evaluations** = **12 million**. Both methods still **2006** for all 3 seeds. Greedy traversed approx 1,788–1,921 complete elite paths per run and found 614k–650k distinct full-DAG-score-2006 neutral schedules within each run; dynamic2 traversed 494–553 paths and made 12,373–12,579 two-move transitions (about 4,950–5,022 involving identified new bottlenecks), finding 323k–352k neutral schedules. These large within-run counts are exploratory visit counts, not individually official-verified certificates, but every selected DAG was evaluated with the checked C++ engine; reported best schedule was independently rescored in Python. More critical-path coordination did not beat greedy objective quality on ta41.

**Stage C: two *far*, officially verified 2006 neutral parents added.**

Unlike the eight earlier mildly different parents, `results/orientation-maxmin-{false,true}/witness` are original CP-generated 2006 schedules whose respective nearest prior-parent Kendall distances were **147 / 141**. Their `upstream-verdict.json` was validated, and `run_elite_relink.py` expanded the protected elite set from 8 to 10. `temp-ta41-elite-far-matched.yml` run `41989468530` completed 6 / 6 × 2 million eval = **12 million**. Both relinking methods still **2006** across seeds. In a uniform 1/256 sample of neutral states, most distant new archived neutral's MINIMUM of all ten originals' 580-adjacent-pair Hamming disagreements was only **52–54**; nearest original Kendall was **71–79**. This did not surpass the two known far CP parents' structural diversity, so avoid describing this as novel basin expansion. Each archive witness was separately verified by Few Shots official `valid=true, score=2006`; paths `results/relink-far-{greedy,dynamic2}-{4107,4113,4129}/neutral-certificate.json`.

**Stage D: memetic local intensification around each of six new relinking neutrals.**

`temp-ta41-memetic-neutral-refinement.yml` run `41989807885`: 6 archived novel neutral parents × 2 local search policies (critical-block tabu, dynamic three-move repair), equal **1 million candidate evaluations each** = **12 million**. Every one of 12 trials independently confirmed **2006**. This tests a constructive composition of elite recombination plus a local improvement kernel, inspired by real 2026 Diaz personal communication on N7 guided tabu and elite path relinking, **without claiming the proprietary true algorithm was implemented**. End-to-end it costs 2m parent-rel linking + 1m local search per arm, so compare both the actual *total* budget and the matched second-stage 1m budget; do not call it better/worse than a 1m tabu trial on a different parent without budget normalization.

**Total completed in stages A-D: ~54 million FULL schedule DAG candidate evaluations**, across multiple parent representations, all **2006**, no verified 2005 witness. This negative *candidate-quality plateau* is evidence against repeatedly scaling the same N7-style block/monotone elite path interface. C++ complete-score throughput is already millions per seconds, so the 2026 Ba–Liu–Yuan batch approximate evaluation speedup is not the immediate blocker here: search *quality/representation* is. The 2026 article's batch algorithm may still be superior for very large neighborhoods, but it was not implemented or refuted here.

**Scientific conclusion, not an excuse to scale:** There is direct evidence that newly critical paths can be recognized and used to coordinate second/third moves, but **no evidence of a makespan quality advantage** for this implementation on ta41. Possible different formulations: joint multi-machine disjunctive orientation repair targeting *sets* of old and predicted replacement critical paths, or scientifically calibrate the algorithm on other Taillard instances with hidden known answers before claiming improvement. Historical 2005 is still only a literature objective without a public full certificate.
