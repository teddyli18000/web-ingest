# NIST G103 hard-output frontier — 2026-10-30

This note records the current constructive frontier for the 32-AND `nist-g103` AES S-box skeleton. It is intentionally separate from the main 2026-10-30 research log so later agents can reuse the stable failure mode without rereading long Action logs.

## Why this skeleton remains attractive

The released seed has 32 AND gates and 71 linear (`XOR`/`XNOR`) gates, total 103. A 68-linear realization on the same nonlinear skeleton would therefore be a valid 100-gate breakthrough.

The public 2025 Extended-BP repository also contains 32-nonlinear AES implementations, but its published AES10 BPD results bottom out at 81 XORs (for example `AES10_BPD_26D_6AD_32NLs_81XORs.py`). Its public tree does not contain an AES10 RNBP result near the current Few Shots boundary. Thus the 71-linear G103 seed is already substantially tighter for this objective than those published Extended-BP AES10 examples.

## Stable true-support RNBP failure mode

Run `41045542990` uses `released_rnbp_support_synth.py` on `nist-g103` with `max_linear=68`, `max_support=8`, and the public Extended-BP sum-distance / max-norm tie-break.

All four completed seeds release all 32 AND atoms and end with exactly two unresolved AES-output targets at the 68-linear budget. Machine aggregation of the four `summary.json` artifacts gives:

- seed 1: `y2=2`, `y6=4`;
- seed 2: `y2=2`, `y6=5`;
- seed 3: `y6=5`, `y7=2`;
- seed 4: `y2=2`, `y6=5`.

Thus **y6 is the genuinely stable hard output across all four seeds**. The second residual output is usually y2 but changes to y7 for seed 3. The earlier provisional statement that the residual pair was always y2/y6 was too strong and should not be reused.

This pattern is still too stable to treat as random tail noise. The current BP tie-break systematically completes easier outputs while stranding y6 at support distance 4–5. In these trajectories all 32 ANDs are already released by roughly the 47th linear helper, leaving about 21 additional linear gates for the output phase. Under `max_support=8`, several outputs — especially y6 — remain `INF` for much of that phase, so they do not influence ordinary reducer scoring until the basis has accidentally moved close enough.

## Search-space change

`g103_hard_output_search.py` adds three output-phase interventions while leaving the strict released-AND construction unchanged before all 32 ANDs are available:

1. `hard`: for equal summed-distance improvement, prefer reducing higher-distance outputs instead of the Extended-BP max-norm concentration rule;
2. `guide`: retain the classic BP objective but prefer helpers that occur in the original 103-gate linear network, preserving output-relevant structure;
3. `cone6`: once all ANDs are released, explicitly reconstruct currently one-gate-available missing helpers from the original transitive linear cone of y6, then resume support-distance RNBP.

Workflow `temp-aes-g103-hard-output.yml`, Run `41047035953`, launches all three interventions across four seeds. Any <=68-linear completion is independently checked on all 256 AES inputs and then sent to the official Few Shots verifier.

The `cone6` intervention is now better motivated than the provisional y2/y6 interpretation: y6 is the only residual target common to every baseline seed.

## Interpretation

The current evidence argues against more random seeds of the same G103 policy. The next useful variable is the *distribution* of support distance across outputs, not just the total distance sum. In particular, any objective that leaves y6 outside the finite-distance horizon until the final few gates is structurally misaligned with the 68-linear target.
